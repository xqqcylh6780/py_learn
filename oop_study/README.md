## 核心速查表

### 属性到底从哪来

```
obj.attr 的查找顺序：
  1. 类里的「数据描述符」     （有 __set__ 或 __delete__）
  2. 实例的 __dict__
  3. 类里的「非数据描述符」   （只有 __get__，普通方法就是这种）
  4. 类属性 / 基类
```

### 三种方法

```python
class C:
    def instance_method(self): ...      # 用 self 的数据

    @classmethod
    def cls_method(cls): ...            # 备用构造器、要用 cls 的多态

    @staticmethod
    def static_method(): ...            # 跟类相关但两者都不需要的纯函数
```

### 常用的魔术方法

| 语法 | 方法 |
|---|---|
| `print(obj)` / `repr(obj)` | `__str__` / `__repr__` |
| `obj == other` | `__eq__`（记得配套 `__hash__`） |
| `len(obj)` / `if obj` | `__len__` / `__bool__` |
| `obj[k]` / `obj[k] = v` | `__getitem__` / `__setitem__` |
| `x in obj` / `for x in obj` | `__contains__` / `__iter__` |
| `obj()` | `__call__` |
| `obj + other` | `__add__` / `__radd__` |
| `with obj` | `__enter__` / `__exit__` |

### 该用哪个

| 需求 | 用什么 |
|---|---|
| 一条不可变的记录 | `namedtuple` |
| 一个有字段、可能要改的东西 | `dataclass` |
| 固定的一组取值 | `Enum` |
| 字段固定、要造几十万个 | `__slots__` |
| 属性赋值要校验 | `@property` 或描述符 |
| 规定「子类必须实现某方法」 | `ABC` + `@abstractmethod` |
| 只关心「有没有这个方法」 | `Protocol` |
| 需要确定性释放资源 | 上下文管理器（`with`） |
| 数据量大、边读边处理 | 生成器 |

## 最容易踩的 10 个坑

1. **类属性里放可变对象**，被所有实例共享（01 节）。
2. 定义了 `__eq__` 却没定义 `__hash__`，对象**突然不能当字典键**（05 节）。
3. `copy.copy()` 是**浅**拷贝，改内层会连累原对象，嵌套结构要用 `deepcopy`（06 节）。
4. `defaultdict` 里用 `d[x]` 读一下，键就**凭空被创建**了。
5. `deque.extendleft([1,2,3])` 插进去是 `3,2,1`，**顺序是反的**。
6. `__setattr__` / `__getattribute__` 里写 `self.xxx` 会**无限递归**，必须用 `object.__xxx__(self, ...)`（13 节）。
7. 子类写了 `__slots__` 而父类没写，或反过来，**内存优化可能完全失效**（08 节）。
8. 运算符重载里该返回 `NotImplemented` 的时候抛了异常，会让报错信息变得莫名其妙（12 节）。
9. `__del__` **不保证被调用**，尤其遇到循环引用；要确定性释放就用 `with`（06、15 节）。
10. `__init__` 在单例里**每次都会执行**，第二次会把第一次的状态覆盖掉（06 节）。
11. 写装饰器忘了 `functools.wraps`，被装饰函数的 `__name__` 变成 `wrapper`，pytest 收集用例、调试器、IDE 提示全受影响（19 节）。
12. `__iter__` 返回 `self`，导致这个对象**只能遍历一次**，第二次就是空的（20 节）。
